Engineering Update

Onboarding, Subscriptions, SMS & Settings

Rebuilt the customer's first experience, clarified shop subscriptions, shipped SMS reminders, and unified the settings design.

Date:  July 16, 2026 Status:  ✓ Delivered & Pushed to main Focus:  Customer UX + growth features

Summary

A heavy product day focused on the customer's first experience and shop subscription management, plus shipping the first real growth feature (SMS) and unifying the settings design. Everything below is implemented, verified against a clean production build, and pushed to main.

1 Login & Sign-Up — Redesigned NEW

We reworked the entire authentication entry point so it feels like a normal modern app rather than a crypto product:

  • "Connect Wallet" → "Log In". Login now leads with Google / Apple / Facebook / Email / Passkey — a wallet is created invisibly behind the scenes, so customers never think about crypto. Connecting an external wallet remains available for those who want it.
  • Dedicated "Sign Up" button (desktop + mobile) with an intent-aware modal — Sign Up shows "Join FixFlow," Login shows "Welcome," using the same secure flow underneath.
  • Removed a broken option: phone/SMS login was failing (needs extra provider setup), so it was removed rather than shown as a dead option on launch day.
  • "Switch Account" button — one click fully logs out (clears session, disconnects wallet, clears cookie) so users can sign in with a different account. Fixed a real testing/UX gap.
  • FixFlow branding applied across all login/sign-up screens (keeping "RepairCoin" as the reward-currency name, per the naming convention).

2 Customer Registration — Hardened FIXED

  • Honest reward messaging. The form promised a "10 RCN bonus" to everyone, but that bonus is only earned with a referral code — a non-referred customer would never get it. The promise is now correctly tied to entering a valid referral code.
  • Inline referral validation. A mistyped code used to fail the entire registration. It's now checked as it's entered (green if valid, clear error if not), so a typo can't block sign-up.
  • Email locked to the verified login identity (read-only), so the stored email can't drift.
  • Required-field validation — name and email show required markers + inline errors instead of silent failures.
  • Privacy Policy consent checkbox added, matching the shop registration flow.
  • Phone number field added (optional, with country-code picker) — wired end-to-end and saved to the customer record, so shops can reach customers.

3 Reliability — Phone Country List FIXED

The phone-number field depended on an external third-party API (RestCountries) that was intermittently failing and throwing errors on a sign-up-critical screen. We bundled the full country list (~165 countries) with the app — instant, offline-safe, no external dependency. Fixed for both customer and shop registration.

4 Subscription Management — Clearer NEW FIXED

  • Added a "Current Plan" card to the shop's Subscription settings showing the plan name (Starter / Growth / Business — previously only the price showed), price, renewal / expiry date, "subscribed since" date, and a prominent "Upgrade / Compare Plans" button.
  • Fixed a visibility bug: shops with the legacy "RCG-qualified" status saw only notification toggles — the actual subscription management (current plan, upgrade, cancel) was hidden. Made that gate blockchain-aware so all shops see it in the current database-only mode. Fully reversible.

5 New Feature — SMS Reminders & Alerts NEW

Shipped the first real growth feature, using the phone numbers we now collect and the existing Twilio integration (previously only used for the ads lead system, not customer notifications):

  • Added SMS as a first-class notification channel to the platform's notification system — so any notification (reminders, alerts, confirmations) can now be delivered by text, not just in-app/push.
  • Wired SMS into booking confirmations and the 24-hour and 2-hour appointment reminders, which already run automatically on a schedule.
  • Safe by design: respects customer opt-out (STOP/START), validates phone format, and only sends when Twilio is configured (a silent no-op otherwise) — ready to flip on with a Twilio number, zero risk until then.
  • Easily extensible to reward alerts ("You earned 25 RCN"), no-show follow-ups, and more.
Why it matters: for a barbershop loyalty product, SMS is the single highest-ROI channel for driving repeat visits — and most of the plumbing was already in place.

6 Unified Settings Design NEW

Rebuilt the customer settings page to match the shop settings layout — a clean two-column design with a left section-nav (Profile · Notifications · Accessibility · Account Standing) instead of one long scrolling page. All existing functionality preserved; the two dashboards now feel consistent.

7 Stability Fix FIXED

Resolved a backend console log-loop (repeated database-connection messages) by disabling a redundant diagnostic self-test — quieter logs and less unnecessary database load. Recommended for production too.

Bottom Line

The customer's first impression — login, sign-up, and registration — is now clean, trustworthy, and crypto-free, while wallet access is preserved and everything is reversible. Shops get a clearer subscription view, the platform gained SMS as a delivery channel (a major engagement lever for a barbershop), and the customer/shop settings now share one polished design. All committed and pushed to main. The remaining go-live items are production operations — Stripe live configuration, deploy, migrations, and (optionally) Twilio credentials to turn on SMS.
